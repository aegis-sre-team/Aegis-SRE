# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Aegis-SRE is a self-healing system for Kubernetes. It reads telemetry (Prometheus, Loki, Falco), diagnoses incidents with an LLM plus a RAG lookup over local runbooks, runs every verdict through a guardrail engine, and then either **heals** an operational failure (restart or scale) or **defends** against a security attack (Cilium eBPF quarantine that keeps the pod alive for forensics). `PHASES.md` holds the phased build plan and the current status of each phase. Phases 1–4 were validated on the `oracle-k3s` cluster, which is gone; the lab is being rebuilt on AWS (`aws/README.md`). Phases 5–7 (Go controller live mode, verify→escalate loop, live dashboard) are **built and tested offline but not verified live**: `k8s/PHASE5_VERIFY.md`, `PHASE6_VERIFY.md` and `PHASE7_VERIFY.md` are the live checklists. The plan's rule: nothing counts as done until it passes against live sensors on a real cluster, not dry-run fakes.

## Commands

All Python runs from the repo root with `PYTHONPATH=.`, because imports are absolute (`from src.brain...`).

```powershell
pip install -r requirements.txt
$env:PYTHONPATH="."; python -m unittest discover -s test -p "test_*.py"   # all tests
$env:PYTHONPATH="."; python -m unittest discover -s test -p "test_guardrails.py"   # one module
$env:PYTHONPATH="."; python -m unittest discover -s test -p "test_guardrails.py" -k <test_name>   # one test
$env:PYTHONPATH="."; python test/test_chaos_benchmark.py                  # chaos / Cloud-OpsBench benchmark

$env:PYTHONPATH="."; python -m src.dashboard.server                       # dashboard, :8000
$env:PYTHONPATH="."; python -m uvicorn src.brain.main:app --port 8001     # diagnostic brain API, :8001

cd controller; go vet ./... && go test ./...                              # Go controller tests (fake clientsets, no cluster)
cd controller; DRY_RUN=true go run .                                       # Go controller, :8080 (Go installed via winget GoLang.Go)
docker compose -f deploy/docker-compose.yml up -d --build                  # full local stack
```

There is no configured linter or formatter. Tests use `unittest` (pytest also works). `test/support.py` must be the first import in every test module: it sets a throw-away DB, disables cloud LLMs, and provides `sensor_patches` (the engine is fail-closed, so tests must stand in for Prometheus/Loki/Falco). `python -m unittest test.test_x` does not work because the stdlib `test` package shadows it; use `discover -s test`.

Images (brain and controller) target an ARM64 K3s node and travel as tarballs, no registry: `BUILD=1 aws/push-image.sh brain|controller` builds with buildx, copies over SSH and imports into K3s. `aws/` holds the AWS CLI scripts (launch/up/down/destroy, `bootstrap.sh`, `apply-stack.sh`, cost guards); none of it has been run against a real AWS account yet. See `PHASES.md` for the apply order.

## Architecture

Pipeline: **collector → metric serializer → RAG → LLM → guardrails → executor → (Go controller | Python kubectl handlers)**.

- `src/brain/diagnostic_engine.py`: the `DiagnosticEngine` orchestrator, which wires the other pieces together. Evidence queries are scoped to `namespace` + exact pod and escaped (`escape_label_value`); a metric with no series is `None`/"no data", never `0 NORMAL`. A trusted Falco signal overrides the LLM to SECURITY_ATTACK/quarantine (`_apply_trusted_signal_policy`), but only when the caller passes `trusted_signal=True` (the Falco ingest, our AlertManager rules and the demo simulator do; `/diagnose` and `/remediate` do not, because an `alert_type` string typed into the API is not evidence); the prompt marks all evidence as untrusted. It **fails closed**: if `TelemetryCollector` reports a critical sensor dark (or raises `SensorDarkError`), it returns a `SENSOR_DARK` / `ESCALATE` verdict instead of inventing healthy metrics. Keep this property. "Honest sensors" is an explicit design goal, so don't add fake default metrics or fake Falco events.
- `src/brain/collector.py`: queries Prometheus and Loki. Falco events are read from Loki stream `{app="falco"}`. That label is a contract with the k8s manifests (Falco DaemonSet label `app: falco`, shipped by Promtail).
- `src/brain/llm_client.py`: provider chain is Ollama (`OLLAMA_HOST`/`OLLAMA_MODEL`, JSON mode) → Groq (`GROQ_API_KEY`, `GROQ_MODEL`) or Gemini → a deterministic **rule-based fallback**, so a diagnosis is always produced even with no LLM. The `_ai_provider` field records which one answered. Verdicts also get persisted to the DB here.
- `src/brain/rag_engine.py`: in-memory TF-IDF over `src/knowledge_base/**/*.md` (`runbooks/` for operational issues, `security/` for MITRE ATT&CK techniques). It resolves the path relative to CWD, so run from the repo root.
- `src/guardrails/`: `action_schema.py` defines `ALLOWED_ACTIONS` (`RESTART_POD`, `SCALE_DEPLOYMENT`, `CILIUM_QUARANTINE_EBPF`, `UNQUARANTINE_POD`, `ESCALATE`), the `CATASTROPHIC_BLOCKLIST`, the pydantic verdict schema, and the `STATE_*` constants. The checks in `validator.py` `GuardrailEngine._evaluate_policy` run in order: schema → blocklist → allowlist → confidence ≥ 0.70 → `SECURITY_ATTACK` + `RESTART_POD` is overridden to quarantine → max 3 restarts per **workload** per hour (key = `workload_key(namespace, pod)`, so a rollout's replacement pods share one budget; the check-and-record is atomic under a lock; the budget is only SPENT by callers that will act: `validate_verdict(..., reserve_budget=False)` peeks without consuming, which diagnose-only paths and `/api/v1/diagnose` use). A missing, non-numeric or out-of-[0,1] `confidence` is invalid and escalates (never defaulted upward), and `UNQUARANTINE_POD` is never approved autonomously (a human releases a cage via the dashboard). Rate limits and decisions persist to the DB, and the engine falls back to in-memory if the DB is unavailable. **A new action must be added in all of these places: the allowlist, the executor router, the Go reconciler, the prompt templates, and the knowledge base.**
- `src/controller/executor.py`: `ActionExecutor.execute_decision` skips anything that isn't `STATE_GUARDRAIL_APPROVED`. Live (not dry-run) it POSTs to the Go controller (`GO_CONTROLLER_URL`, bearer `GO_CONTROLLER_TOKEN`, namespace from `decision.namespace`) and **fails closed** if the controller is unreachable; the `kubectl` handlers only run in dry-run or with `AEGIS_ALLOW_KUBECTL_FALLBACK=true` (local dev). Quarantine persists the controller's real forensics to `logs/forensics_<pod>.json` (dry-run files contain no process data, only `DRY_RUN_NO_CLUSTER_DATA`). A live decision with no namespace is refused (`FAILED_NO_NAMESPACE`; the executor default `default` is only used in dry-run). A controller that answers `mode: dry_run` while the brain is live is reported as `FAILED_CONTROLLER_DRY_RUN` (nothing changed). Dry-run results report `dry_run: true` and `health_verified: null` in `to_dict()` and every audit record (the attribute stays True only for in-process callers). Controller actions are verified through the controller even when the kubectl-fallback flag is set (`use_kubectl=False`). The kubectl SCALE fallback scales UP by one, capped at `MAX_REPLICAS` (never down). Kubectl fallback resolves the owner KIND (`deployment/x`, `statefulset/x`, `daemonset/x`). Quarantine DB rows are keyed `"<namespace>/<pod>"` inside the existing unique `target_pod` column and are never written in dry-run. A real forensics snapshot is never overwritten (`_forensics_target`: later captures go to timestamped files). `verify_remediation_health` polls the controller's `/api/v1/status`; unreachable or timed out means unhealthy. `cilium_policy.py` builds the quarantine policy.
- Quarantine design (must stay identical in `src/controller/cilium_policy.py` and `controller/quarantine.go`): the pod is labelled `aegis.io/quarantine-target=<label value>` (pod name, or first 52 chars + `-` + 10 hex of sha256 when longer than 63) and a CiliumNetworkPolicy selects that label with `ingressDeny`/`egressDeny` on entity `all`. Cilium endpoints do not carry the pod name as a label and empty `ingress: []` rules are invalid, so the earlier approach could not work. Unproven until `PHASE5_VERIFY.md` passes on a real cluster.
- `src/brain/remediation.py`: `process_alert` is the single path alert → diagnose → guardrails → execute → verify → escalate (it escalates on unapproved, failed execution, failed verification, or an explicit ESCALATE). `AlertDebouncer` (thread-safe, bounded, `release` on failure) drops repeat events for both ingest endpoints. They only act when `AEGIS_AUTO_REMEDIATE=true` (then the work runs in a background task and the response is `accepted`); otherwise they just diagnose. Ingest validates pod/namespace names (DNS-1123), ignores Falco events outside the managed namespaces before any LLM call, and every action endpoint (including the `/api/v1/controller/*` router) can require `AEGIS_INGEST_TOKEN`; `IncidentRequest` validates `pod_name`/`namespace` (DNS-1123) and `alert_type` (`^[A-Za-z0-9_.:-]{1,64}$`) -> 422. `process_alert()['verified']` is `None` in dry-run.
- `controller/` (Go, client-go): the only component that mutates the cluster. `validateRequest` (approved, allowlisted action, namespace required, protected namespaces `kube-system/kube-public/kube-node-lease/aegis-system/monitoring/cilium-secrets`, optional `ALLOWED_NAMESPACES`) runs before any cluster call. Restart = rollout restart of the owning Deployment (resolved via owner references); scale = +1 capped at `MAX_REPLICAS`; quarantine = forensics first, then label + deny policy; all idempotent. A restart only deletes pods controlled by a ReplicaSet/StatefulSet/DaemonSet (bare and Job pods get HTTP 422); `replicas < 1` is rejected (400); a second quarantine of an already-isolated pod is a no-op that keeps the first evidence. HTTP API: `/healthz`, `/api/v1/reconcile`, `/api/v1/status` (includes `terminating`), `/api/v1/pods`; `CONTROLLER_TOKEN` auth requires the `Bearer ` scheme (a bare token is rejected); `DRY_RUN` defaults to true. Tests use client-go fake clients, so they prove logic, not RBAC or Cilium behaviour.
- `src/db/`: SQLAlchemy models (incidents, quarantines, audit, restart events, guardrail decisions). `DATABASE_URL` defaults to SQLite under `AEGIS_DB_DIR` (`logs/`). Neon Postgres is used in-cluster. Tests call `configure_database(...)` to point at a temp SQLite file.

### Two FastAPI apps

- `src/brain/main.py` (port 8001) is the in-cluster brain. It exposes `/health`, `/api/v1/diagnose`, `/api/v1/alerts/webhook` (AlertManager ingest; maps alert labels to alert types in `_alert_type_from_labels`), `/api/v1/alerts/falco` (Falco `http_output`; only `Aegis ...` rules that name a pod and namespace) and `/api/v1/remediate`. Alert handlers are plain `def` on purpose: they block (LLM, verification polling) and must not run on the event loop. Execution is dry-run unless `AEGIS_DRY_RUN=false` (and the controller's `DRY_RUN=false`). The namespace always comes from the alert, never from the LLM.
- `src/dashboard/server.py` (port 8000) is the mission-control UI (static files in `src/dashboard/static/`). It provides WebSocket telemetry at `/ws/telemetry`, chaos trigger, HITL escalation resolve, forensics, and postmortem endpoints. `DASHBOARD_MODE` (`auto|live|demo`) picks live cluster state (`src/dashboard/live_state.py`: pods from the controller, CPU/mem from Prometheus) or a labelled simulated demo; every payload carries `data_source`. Forensics return 404 in live mode when nothing was captured, the chaos trigger is demo-only, and HITL actions go through the real executor (namespace required in live mode, same namespace policy as autonomous actions; the two POST endpoints can require `AEGIS_DASHBOARD_TOKEN`, which the UI asks for once). New audit rows stream as `PIPELINE_EVENT` (so dashboard and brain must share `DATABASE_URL`). At startup it restores active quarantines from the DB.

### Manifest / config locations

- `k8s/` is the **canonical cluster path** used by `PHASES.md`. It covers namespaces (`online-boutique`, `aegis-chaos`, `aegis-system`, `monitoring`), Online Boutique, chaos scenarios in `k8s/chaos/`, monitoring (Falco posts events to the brain), the brain, the Go controller (`k8s/controller/`: namespaced Roles for `online-boutique` and `aegis-chaos` only, never a ClusterRole), and Cilium install helpers. Per-phase verification steps live in `k8s/PHASE*_VERIFY.md`.
- `deploy/` (docker-compose + `deploy/k8s/`) and `config/` hold the local Compose stack. `test/` also contains a separate hands-on lab (its own compose, k8s, and sensor configs) in addition to the unit tests.

## Gotchas

- Runtime output goes to `logs/` (JSONL audit logs, SQLite DB, benchmark reports), which is mostly gitignored. `logs/guardrail_audit.jsonl` is tracked and gets modified by test runs. Don't commit that churn.
- The repo directory holds secrets that are gitignored: `.env`, the `ssh-key-*.key` files, `oracle-k3s.yaml` (kubeconfig for the dead cluster), and the image tarballs (`aegis-*.tar`). Never stage them. `k8s/cilium/values-k3s.yaml` is deliberately un-ignored (an exception to the `*k3s.yaml` rule) because `aws/apply-stack.sh` needs it.
- Env switches worth knowing: `AEGIS_DRY_RUN`, `AEGIS_AUTO_REMEDIATE`, `AEGIS_ALLOWED_NAMESPACES`, `AEGIS_ALLOW_KUBECTL_FALLBACK`, `AEGIS_ALERT_DEBOUNCE_S`, `AEGIS_INGEST_TOKEN`, `AEGIS_DASHBOARD_TOKEN`, `VERIFY_TIMEOUT_S`, `DASHBOARD_MODE`; controller side `DRY_RUN`, `MAX_REPLICAS`, `ALLOWED_NAMESPACES`, `CONTROLLER_TOKEN`.
- The dev machine runs Windows. The README shows both PowerShell and bash forms of each command.

## Git workflow

- Do not commit unless the user explicitly says to. When told to, make small, atomic commits.
- Commit messages are a single line only: no body and no `Co-Authored-By` trailer (this overrides any default attribution).
- Never include `logs/guardrail_audit.jsonl` churn in a commit.
